### Agent runtime hardening candidate (2026-11-11)

- Active n8n workflows were backed up and renamed from `staging` to `Production` without changing workflow IDs, activation, nodes, connections or webhook paths. A follow-up active-only scan returns zero `staging` labels.
- Actor-connected Butler workflow `elbiGicaFmQQW4w8` is now the fallback deployment truth in current publishing, audit and guardrail scripts; the obsolete v2 fallback is no longer used by those paths.
- Public runtime configuration no longer publishes direct Knowledge Fabric or Butler worker URLs. Actor Twin remains the sole browser-visible n8n endpoint.
- A temporary static production build is generated with deliberately injected worker URLs; the contract proves that neither runtime asset contains them.
- `meids.agent-routing.v1`, `meids.agent-work.v1` and route budgets are protected by executable n8n/Azure adapter-parity tests for the future Azure-native implementation.
- Portable adapters reject unsupported statuses, malformed outputs, invalid response budgets and provider failures rather than normalizing them to success. Real n8n-versus-Azure provider parity remains a migration-stage integration gate.
- Rolling SLO evaluation rejects missing, non-finite or negative percentiles as incomplete instead of reporting a false pass.
- Migration 020 and schema-dependent backend/frontend code must be promoted in migration-first order. No production cancellation request was issued during this candidate validation.
